Git identities

The clone URL picks name, email, SSH key, and signing key — not the folder. Day-to-day staging lives in lazygit.

Check git whoami

Clone patterns (memorize)

Remote URLIdentity
git@github.com:owner/repo.gitpersonal
git@github.com-work:org/repo.gitwork
git@github.com-freelance:c/repo.gitfreelance
git@github.com-oss:proj/repo.gitopen-source

HTTPS remotes won’t match includeIf rules — switch to the SSH host alias. Upload each public key twice on GitHub: Authentication and Signing.

Common flows

  1. Clone as the right person

    Use the host alias in the URL → git whoami before the first commit.

  2. Fix a wrong remote

    git remote -v → set URL to git@github.com-work:… → git whoami again.

  3. Daily commit (TUI)

    lg or Space gg — signing happens automatically when user.signingkey is set.

Reach for this instead

  • One global user.email forever→clone URL picks identity
  • Guess which key ssh uses→core.sshCommand per identity
  • Hope no secrets landed→gitleaks pre-commit

Drills

  • In this repo, run git whoami and git config --get user.signingkey. Both should resolve via includeIf + identity file.
  • Read git remote -v and say which identity rule matched — out loud. If none match, commits fail by design.
