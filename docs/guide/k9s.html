k9s

The lazygit of Kubernetes — vim keys, logs, exec, port-forward. Shell alias k is kubecolor-wrapped kubectl for one-off commands.

Launch k9s · context: kubectx · namespace: kubens

Keybinds

: podsJump to pods view (also :deploy, :svc, …)
: nsNamespaces

/Filter resources

Ctrl+c / :qQuit

Outside k9s: kgp / kcc (current context) / kgctx / kuc / kns, or stern <prefix> for multi-pod logs. kubectx/kubens also work for switching.

Common flows

  1. Find a crashing pod

    k9s → :pods → / filter by name → select → l logs → d if you need events.

  2. Exec and poke around

    Select pod → s → shell → exit → still in k9s.

  3. Port-forward a service locally

    Select pod/svc → Shift+F → set ports → test in browser → stop forward when done.

Reach for this instead

  • kubectl get pods -A | grep→k9s → / filter
  • kubectl logs -f …→k9s → l
  • kubectl exec -it … -- sh→k9s → s

Drills

  • Against kind (or Colima k3s on work): open k9s, switch to pods with :pods, filter, open logs, go back. No kubectl for this drill.
  • From the shell, use k get ns once, then do the same discovery only inside k9s. Feel when TUI beats one-liners.
